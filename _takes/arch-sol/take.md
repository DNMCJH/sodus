# 结论
daemon应收束核心；首修双执行入口：mcp.py 旧工具直连 DB/runner，server 启动却回收非己 run；文档禁并用。

# 目标分层
宿主→MCP/CLI/HTTP适配→应用服务→core（状态机、路由、账本、记忆审核、策略、认证、事件）→DB/执行端口。执行适配含 runner/agents/profiles、propose/verify，保留隔离与验收。DSH/看板/pet/聊天、tdd/review/fix、dream 提取与调度在外；记忆版本、审批与日志恢复在内。

# Q1–Q5
Q1：单入口指统一服务契约，不是单宿主。HTTP 为权威，stdio MCP 与 CLI 转发；旧工具也迁移。install --host：三宿主预览、备份、幂等合并、卸载、握手；不注入worker。凭据绑定身份，规范路径定workspace，宿主+会话ID定session，续问显式关联。环境 role/depth 会误伤继承变量的外部 agent，且裸 HTTP 可绕过；改服务端签发父run/深度与禁派生凭据。

Q2：先模块化、保持单 daemon+worker 子进程，不另建执行服务。HTTP/OpenAPI /v1增量兼容；事件带版本/序号，DB独立迁移、不对外。先转发入口，再抽服务、移展示/调度；保留旧别名。

Q3：推荐 A 为默认、B 可选。A 少一跳、保留上下文，故障可本地退路，成本低但双执行难追踪；B 多排队/上下文交接，执行故障集中，统一日志好调试，但需裁剪工具与重做权限。受管项目可选B，由宿主禁写。

Q4：值得做，先接口后面板。v1 估3–5人日：run、needs-you、失败、今日分币种花费、ask队列、记忆候选数量及跳转；不做合入/审核。用正式 slot，保留默认图标；pet图标靠DOM、adaptive-width靠CSS，升级易坏。宿主代理鉴权，前台5秒轮询/board；SSE无全局补放。以后事件触发重拉，重连全量。浏览器管审核，pet/tray提醒。

Q5：路线。

# 风险
配置隔离不等于文件沙箱；非git ask仍能写。dream 仅扫当前 workspace、失败占当天窗口且采纳延迟（HANDOFF）。防状态、锁、计费漂移。

# 路线
1. 统一所有权：MCP退出、daemon重启后无误判/重复执行。
2. 安装器：三宿主握手成功，重复安装一致、卸载保留他项。
3. 身份链：外部可派活，worker省略深度头仍被拒。
4. 核心契约：适配层不直写DB，跨版本契约测试通过。
5. 记忆调度：双workspace可重试；采纳即应用，崩溃恢复幂等。
6. 面板：断线恢复且与board一致，DSH升级冒烟通过。
不做多租户、执行集群、强制瘦DSH、第二套看板。

SUMMARY：先统一所有权。
