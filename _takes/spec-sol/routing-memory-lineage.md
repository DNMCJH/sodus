# 三层：能力路由、记忆、会话血缘

这份文档回答一个设计问题：**同一个 Sodus，怎么把"不同难度、不同类型"的活，分给"最合适的执行者"，并且每次都比上一次更聪明。**

结论先说：Sodus 原来是「派活 → 收文件 → 跑测试判决 → 记账」，是一条生产线。要变成会积累的系统，还差三块拼图——按难度分配、记忆、血缘。三块都围绕同一件事：**下一次派活时，用上上一次的结论。**

## 一、能力路由（不是故障回退）

现有 `route` 只做一件事：一个执行者**可证没干活**时换下一个。这是可靠性，不是分配。

要补的是**派活前的判断**：

```
任务文本 → assess(难度1-5, 类型, 所需能力) → recommend(路由 + 理由 + 备选) → 派活 → 记录判断
```

- 判断分两段：先规则（关键词、是否含代码、长度、是否要求重构/分析/调研），有 Jev 时用 Jev 复核并给出置信度
- 没有 Jev 就明说 `basis="rules-only"`，**不假装有模型判断**
- 推荐必须带依据：有实测数据的路由引用数据，没数据的一律标 `unknown`，不许编
- 判断写进 run 的事件流，事后能回答"当时为什么派给它"

这一块的真正闭环在评测集：`nodus bench` 跑出每类任务的 solve 率、耗时、成本，喂给 `recommend`。**没有评测数据的路由推荐就是猜。**

## 二、记忆：三档作用域

| 作用域 | 谁写得进 | 谁读得到 | 典型内容 |
|---|---|---|---|
| `private` | 单个 agent | 只有它自己 | 它的工作习惯、踩过的坑、"这个项目里别用 X" |
| `project` | 项目内所有执行者 | 同一个 workspace | 构建命令、目录约定、已确认的架构决定 |
| `public` | 任何人 | 全部 | 跨项目通用的经验、工具用法 |

规则：
- 同 key 覆盖（更新比追加更重要），保留 `updated_at`
- 检索先用关键词匹配，**不引入向量库**——现在没这个必要，加了就是负担
- 派活时只注入**非空且相关**的记忆，并标明来源；空就什么都不加
- `private` 的隔离要在查询层实现，不能靠"大家自觉"

记忆的价值不在存，在**注入**：同一个 agent，第二次做同类任务时 brief 里多了三条已验证的事实，比换更强的模型更有效。

## 三、会话血缘：打通与续接

现在会话能 `resume`（接着聊）和 `branch`（分叉），但它们是**孤立的记录**，没有"这次会话从哪来、往下派生了什么"。

要补的是一条链：

```
session ──resume──> session ──branch──> session
   │                    │
   └── run ── handoff ──┴──> run（含 worktree / proposal）
```

有了血缘才能回答：
- 这个任务历史上试过什么、哪一次成功了
- 这个提案是哪个会话、哪个 run 产出的
- 同一个问题换路由重试过几次（这才是"该给谁"的真实依据）

实现上不新建体系：`session` 表加 `parent_session_id` / `origin_run_id`，run 已有 `parent_run_id`，proposal 已有 `run_id`。查询层给一个 `nodus lineage <session|run>` 就够了。

## 四、三者怎么串起来

一次派活的完整路径：

```
1. assess(task)                 ← 难度与类型
2. memory.harvest(project)      ← 各 harness 的 CLAUDE.md / AGENTS.md 里抽出来的候选事实
3. recommend(assess)            ← 路由建议（有评测数据时用数据）
4. dispatch（brief = 任务 + 约束；会读文件的 harness 不再重复注入记忆）
5. verify（测试 exit code + 文件 hash）  ← 唯一的判决
6. record（判断、成本、结果、耗时）
7. adopt                        ← 人看板审核后写进项目 AGENTS.md 的「已验证事实」
```

第 7 步是这版的重点，而且**采纳这一下必须是人**。要小心：自动把 agent 的自述写成记忆，等于把错误固化。所以 `remember` 只写人被要求写的那一条，`harvest` 抽出来的候选一律先上板，等人点。

## 六、边界

- 记忆和血缘都是**基础设施**，没有评测数据支撑的路由策略就是感觉，别急着上
- 汇总会抽出重复和噪音：规则只认得列表项、小节标题和祈使句，抽不到的事实就是抽不到，
  别指望它代替人读一遍（冲突检测更粗，见 `memory.py` 的说明）
- 全局文件里的规则一旦被采纳进项目 `AGENTS.md`，对三方同时生效；采纳前确认它真的适用于这个项目
